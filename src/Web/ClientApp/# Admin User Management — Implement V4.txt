## 3. User Status System (v3)

### 3.1 Enum — `UserStatus`

```csharp
public enum UserStatus
{
    Active = 0,      // Hoạt động bình thường
    Inactive = 1,    // 30+ ngày không login
    Suspended = 2,   // Khóa tạm thời (admin set thời hạn)
    Banned = 3,      // Ban vĩnh viễn
}
```

### 3.2 Lưu trữ — Column trong `ApplicationUser`

```csharp
public class ApplicationUser : IdentityUser
{
    // ... existing fields ...
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    public UserStatus Status { get; set; } = UserStatus.Active;
}
```

> [!NOTE]
> **Tại sao lưu column thay vì computed?**
> - Filter/query đơn giản: `WHERE Status = @status` (thay vì complex LockoutEnd logic)
> - 4 trạng thái rõ ràng, không cần tính toán mỗi lần
> - `LockoutEnd` vẫn giữ để biết ngày hết hạn Suspend

### 3.3 Flow chuyển trạng thái

```mermaid
stateDiagram-v2
    [*] --> Active : Register / Add User
    Active --> Inactive : 30 ngày không login (background job)
    Active --> Suspended : Admin suspend
    Active --> Banned : Admin ban
    Inactive --> Active : User login lại
    Inactive --> Suspended : Admin suspend
    Inactive --> Banned : Admin ban
    Suspended --> Active : Hết hạn + login lại / Admin unban
    Suspended --> Banned : Admin ban (nâng mức)
    Banned --> Active : Admin unban
```

### 3.4 Login Flow (đã implement)

```
User login →
  ├── Status = Banned      → Block: "Your account has been permanently banned."
  ├── Status = Suspended
  │     ├── LockoutEnd > now  → Block: "Account suspended until {date}."
  │     └── LockoutEnd <= now → Auto reactivate → Active → login OK
  ├── Status = Inactive    → Reset to Active → login OK
  └── Status = Active      → login OK
```

### 3.5 Inactive Detection — Hangfire Background Job

```csharp
// Chạy mỗi ngày lúc 2:00 AM (chưa implement, sẽ làm sau)
RecurringJob.AddOrUpdate<IUserStatusJob>(
    "mark-inactive-users",
    job => job.MarkInactiveUsersAsync(),
    Cron.Daily(2));
```

Logic: User Active mà `LastLoginTime` null + `CreatedAt > 30 ngày` HOẶC `LastLoginTime > 30 ngày` → set Status = Inactive.

## 4. Phân Tích Kỹ Thuật

### 4.1 Joined Date — `CreatedAt`

**Không có sẵn** trong Identity → đã thêm `CreatedAt` vào `ApplicationUser`. Cần migration.

### 4.2 Last Login — `LastLoginTime`

**Đã có sẵn.** Cập nhật tại `Login()` method mỗi lần login. Nullable — `null` = chưa bao giờ login.

### 4.3 Online Status — `ConnectionManagerService`

Singleton in-memory `ConcurrentDictionary<userId, HashSet<connectionId>>`. User có SignalR connection = online. Đã thêm `GetAllOnlineUserIds()` và `GetOnlineCount()`.

### 4.4 Change Role

Dùng `UserManager` APIs: `RemoveFromRolesAsync` → `AddToRoleAsync`. Chỉ có 2 roles: `User` và `Administrator`. User cần refresh token/re-login sau khi đổi role.

### 4.5 Ban/Unban/Suspend

- **Ban**: `user.Status = Banned` + `LockoutEnd = MaxValue`
- **Suspend**: `user.Status = Suspended` + `LockoutEnd = now + N days`
- **Unban**: `user.Status = Active` + `LockoutEnd = null`
- Tất cả vẫn set `LockoutEnabled` để tương thích code cũ (`GetUserById`)

## 5. Backend Endpoints

### 5.1 Tổng quan

| # | Endpoint | Method | Mục đích |
|---|---|---|---|
| 1 | `/api/User/admin` | GET | Danh sách users (paginated + filter) |
| 2 | `/api/User/admin/{id}` | GET | Chi tiết 1 user |
| 3 | `/api/User/admin/add-user` | POST | Tạo user mới (role = User) |
| 4 | `/api/User/admin/ban` | PUT | Ban user vĩnh viễn |
| 5 | `/api/User/admin/suspend` | PUT | Suspend user có thời hạn |
| 6 | `/api/User/admin/unban` | PUT | Unban/Unsuspend user |
| 7 | `/api/User/admin/change-role` | PUT | Đổi role |

### 5.2 GET `/api/User/admin` — Danh sách Users

**Query Params:** `searchText`, `roleFilter`, `statusFilter` (Active/Inactive/Suspended/Banned), `sortBy` (newest/name/lastLogin), `pageNumber`, `pageSize`

**Response DTO (`AdminUserListItemDto`):**
```json
{
  "items": [{
    "id": "guid", "fullName": "Nguyễn Văn A", "email": "a@gmail.com",
    "avatar": "url", "roles": ["User"], "status": "Active",

    "enrolledCourseCount": 5, "createdCourseCount": 2, "isOnline": true
  }],
  "pageNumber": 1, "totalPages": 10, "totalCount": 298
}
```

### 5.3 GET `/api/User/admin/{id}` — Chi tiết User

**Response DTO (`AdminUserDetailDto`):**
```json
{
  "id": "guid", "fullName": "...", "email": "...", "phoneNumber": "...",
  "avatar": "...", "headline": "...", "roles": ["User"],

    { "courseId": 10, "courseTitle": "Vue.js", "status": "Published", "totalStudents": 120, "ratings": 4.5 }
```

### 5.4 POST `/api/User/admin/add-user`

**Request:** `{ "email": "...", "fullName": "...", "password": "..." }`
**Logic:** Gọi `Register()` hiện có → role `"User"`, Status = Active.

### 5.5 PUT `/api/User/admin/ban`

**Request:** `{ "userId": "guid", "reason": "..." }`
**Logic:** Set `Status = Banned`, `LockoutEnd = MaxValue`. Không tự ban mình.

### 5.6 PUT `/api/User/admin/suspend`

**Request:** `{ "userId": "guid", "durationDays": 7, "reason": "..." }`
**Logic:** Set `Status = Suspended`, `LockoutEnd = now + durationDays`. Không tự suspend mình.

### 5.7 PUT `/api/User/admin/unban`

**Request:** `{ "userId": "guid" }`
**Logic:** Set `Status = Active`, `LockoutEnd = null`. Dùng cho cả unban VÀ unsuspend sớm.

### 5.8 PUT `/api/User/admin/change-role`

**Request:** `{ "userId": "guid", "newRole": "Administrator" }`
**Logic:** `RemoveFromRolesAsync` → `AddToRoleAsync`. Không tự đổi mình.
